## 구글맵 마커 클러스터링 도입기 — 줌 레벨에 따라 마커 뭉치기

지도 위에 여러 지점을 마커로 찍는 화면이다. 처음엔 데이터마다 `<Marker>` 하나씩 그냥 뿌렸다. 개수가 적을 땐 멀쩡했다.

문제는 마커가 수백 개로 늘고, 사용자가 지도를 **축소**하는 순간 터졌다. 좁은 화면에 마커 수백 개가 겹쳐 **떡이 지고**, 어디에 몇 개가 있는지 전혀 안 보였다.

### 1. 기본형 — Marker를 그냥 다 찍는다

기본 구조는 이렇다. `points` 배열을 돌면서 `<Marker>`를 하나씩 렌더한다.

```tsx
interface Point {
  id: string
  name: string
  lat: number
  lng: number
}

const points: Point[] = [
  { id: 'A', name: '지점A', lat: 37.2756, lng: 127.0543 },
  { id: 'B', name: '지점B', lat: 36.522, lng: 127.303 },
]

<GoogleMap mapContainerStyle={containerStyle} center={center} zoom={8}>
  {points.map((p) => (
    <Marker
      key={p.id}
      position={{ lat: p.lat, lng: p.lng }}
      title={p.name} // hover 시 툴팁
      onClick={() => setSelected(p)}
    />
  ))}
</GoogleMap>
```

마커가 10개면 완벽하다. 하지만 300개가 되고 줌을 4까지 빼면, 넓은 영역 화면에 마커 300개가 서로 포개진다.

<Callout type="error" label="문제:">
  낮은 줌에서 마커가 전부 겹쳐 **클릭도 안 되고 개수 파악도 안 된다.** "이 지역에 마커가 몇 개 있나"라는 가장 기본적인 정보를 지도가 못 준다.
</Callout>

<br />

### 2. 목표 — 가까운 마커를 하나로 뭉친다

해법은 **클러스터링**이다. 서로 가까운 마커를 하나의 "클러스터 마커"로 합치고, 거기에 개수를 표시한다. 그리고 **줌을 당길수록 뭉치는 반경을 좁혀서** 점점 개별 마커로 풀어준다.

### 3. 클러스터링 알고리즘 뜯어보기

핵심 함수는 `clusterMarkers` 하나다. 세 가지 아이디어로 되어 있다.

```tsx
const clusterMarkers = (positions: PositionProps[], zoom: number, variable: number) => {
  const clusterRadius = variable / zoom // ① 줌이 클수록 반경이 작아짐
  const clusters: ClusterPositionProps[] = []

  positions.forEach((position) => {
    // ② 이미 만들어진 클러스터 중 "반경 안"에 있는 걸 찾는다
    const foundCluster = clusters.find(
      (cluster) =>
        Math.abs(cluster.lat - position.lat) < clusterRadius &&
        Math.abs(cluster.lng - position.lng) < clusterRadius,
    )

    if (foundCluster) {
      // ③ 있으면 → 흡수 (중심좌표를 누적 평균으로 갱신)
      foundCluster.lat =
        (foundCluster.lat * foundCluster.count + position.lat) / (foundCluster.count + 1)
      foundCluster.lng =
        (foundCluster.lng * foundCluster.count + position.lng) / (foundCluster.count + 1)
      foundCluster.count += 1
      foundCluster.names.push(position.name)
    } else {
      // 없으면 → 새 클러스터 시작
      clusters.push({
        lat: position.lat,
        lng: position.lng,
        count: 1,
        names: [position.name],
      })
    }
  })

  return clusters
}
```

#### ① 반경은 줌에 반비례 — `variable / zoom`

줌 숫자가 커질수록(=확대할수록) 반경이 작아져 덜 뭉친다. `variable`은 구간별로 주입하는 계수다. 이 둘의 곱으로 "이 줌에서 얼마나 가까워야 한 덩어리로 볼까"를 정한다.

#### ② 반경 판정 — 위·경도 차의 절댓값

두 점이 가까운지를 **위도 차·경도 차의 절댓값**이 각각 반경보다 작은지로 본다. 정확한 원이 아니라 **정사각형 박스** 판정이다. 한국처럼 좁은 영역에선 충분히 잘 동작한다.

#### ③ 흡수 — 중심좌표를 누적 평균으로

클러스터에 새 점이 들어오면 `(기존중심 × 개수 + 새점) / (개수 + 1)`로 중심을 다시 계산한다. 증분 평균(incremental mean)이라 덩어리가 커질수록 중심이 실제 무게중심으로 수렴한다.

<Callout type="tip" label="핵심:">
  라이브러리 없이도 클러스터링의 뼈대는 단순하다. **"반경 안이면 흡수, 아니면 새로 시작"** 이 그리디(greedy) 한 줄이 전부다. 화려한 알고리즘보다 이 단순함이 유지보수엔 오히려 유리했다.
</Callout>

<br />

### 4. 줌 구간별 파라미터 — `variable` 버킷

`variable`을 줌 구간마다 다르게 준다. "세계 뷰에선 크게 뭉치고, 확대하면 개별로 풀리는" 곡선을 이걸로 만든다.

```tsx
useEffect(() => {
  if (zoom < 5) {
    setClusters(clusterMarkers(positions, zoom, 20)) // 아주 크게 뭉침
  } else if (zoom >= 5 && zoom < 8) {
    setClusters(clusterMarkers(positions, zoom, 4)) // 중간
  } else if (zoom >= 8 && zoom < 10) {
    setClusters(clusterMarkers(positions, zoom, 0.1)) // 거의 안 뭉침
  } else {
    // zoom >= 10 : 클러스터링 끄고 전부 개별 마커
    setClusters(
      positions.map((position) => ({
        lat: position.lat,
        lng: position.lng,
        count: 1,
        names: [position.name],
      })),
    )
  }
}, [zoom, positions])
```

실제 반경(`variable / zoom`)을 계산해보면:

| 줌 구간    | variable | 예시 줌 | 실제 반경(도) | 효과               |
| ---------- | -------- | ------- | ------------- | ------------------ |
| zoom < 5   | 20       | 4       | 5.0           | 광역으로 크게 뭉침 |
| 5 ≤ z < 8  | 4        | 6       | 0.67          | 도시 단위로 뭉침   |
| 8 ≤ z < 10 | 0.1      | 8       | 0.0125        | 거의 개별에 가까움 |
| z ≥ 10     | —        | —       | —             | 클러스터링 off     |

<Callout type="tip" label="설계 의도:">
  줌이 연속적으로 반경을 줄이면(`/zoom`) 자연스럽지만, 그것만으론 세계 뷰에서 충분히 크게 안 뭉친다. 그래서 `variable`을 구간별로 계단식으로 크게 줘서 **낮은 줌일수록 과감하게 뭉치게** 했다.
</Callout>

### 5. 렌더링 — 클러스터/단일을 아이콘과 라벨로 구분

계산된 `clusters`를 돌면서 `count`로 분기한다. **아이콘·크기·라벨**을 전부 다르게 준다. 클러스터면 `+개수`, 단일이면 마커 이름 앞 4글자를 라벨로 띄운다.

```tsx
{clusters?.map((cluster, index) => (
  <Marker
    key={index}
    // 호버 중인 마커를 맨 위로, 나머지는 위도 기준으로 z 정렬
    zIndex={hoveredMarker?.names === cluster.names[0] ? 20000 : Math.round(cluster.lat * 100)}
    position={{ lat: cluster.lat, lng: cluster.lng }}
    icon={{
      url: cluster.count > 1 ? './cluster_marker_normal.png' : './location_icon_last.png',
      scaledSize: cluster.count > 1 ? new google.maps.Size(40, 40) : new google.maps.Size(38, 60),
      labelOrigin:
        cluster.count > 1 ? new google.maps.Point(20, 20) : new google.maps.Point(19, 50),
      anchor: new window.google.maps.Point(23, 30),
    }}
    label={{
      text: cluster.count > 1 ? `+${cluster.count}` : cluster.names[0].substring(0, 4),
      fontSize: '12px',
      fontWeight: 'bold',
      color: '#222',
    }}
    onClick={handelOnMouseOver(cluster)}
    onMouseOver={() => {
      document.body.style.cursor = 'pointer'
    }}
    onMouseOut={() => {
      document.body.style.cursor = 'default'
    }}
  />
))}
```

#### zIndex — 겹칠 때 뭐가 위로 오나

마커가 겹치면 클릭·라벨 가독성 때문에 **쌓임 순서**가 중요하다. 두 가지 규칙을 뒀다.

- **호버 중인 마커**는 `zIndex = 20000`으로 최상단
- 나머지는 `Math.round(cluster.lat * 100)` — **위도가 높을수록(북쪽일수록) 위로**. 지도에서 아래쪽(남쪽) 마커가 위쪽 마커를 가리지 않게 하는 관례다.

<br />

### 6. 상호작용 — 단일 마커에만 InfoWindow

마커를 클릭하면 상세정보 창(`InfoWindow`)을 띄운다. 단, **클러스터(여러 개 뭉침)엔 안 띄운다.** 뭉쳐 있는 상태에선 대표 하나의 좌표만 보여줘봐야 의미가 없기 때문이다.

```tsx
const handelOnMouseOver = (cluster: ClusterPositionProps) => () => {
  if (cluster.names.length === 1) {
    // 단일 마커일 때만 상세창 대상 지정
    setHoveredMarker({
      names: cluster.names[0],
      lat: cluster.lat,
      lng: cluster.lng,
    })
  } else {
    // 클러스터는 상세창 없음 (줌인해서 풀어야 함)
    setHoveredMarker(null)
  }
}
```

#### InfoWindow가 마커를 가리는 문제 — 줌 기반 오프셋

`InfoWindow`를 마커 좌표 그대로 띄우면 **말풍선이 마커를 덮는다.** 그래서 위도에 약간의 오프셋을 더해 마커 **위쪽**에 띄운다. 문제는 이 오프셋이 줌에 따라 체감 크기가 달라진다는 점이다. 그래서 오프셋도 줌에 반응시킨다.

```tsx
const getLatOffset = (zoom: number) => {
  return 0.05 * Math.pow(2, -zoom + 10) // 줌이 낮을수록(멀수록) 더 큰 오프셋
}

// ...
;<InfoWindow
  position={{ lat: hoveredMarker.lat + getLatOffset(zoom), lng: hoveredMarker.lng }}
  onCloseClick={() => setHoveredMarker(null)}>
  <Box sx={{ padding: '10px', display: 'flex', flexDirection: 'column', alignItems: 'center' }}>
    <StyledTypo fontSize={14} fontWeight={500}>
      Name : {hoveredMarker.names}
    </StyledTypo>
    <Table sx={{ marginTop: '20px' }}>
      <TableHead>
        <TableCell>lat</TableCell>
        <TableCell>{hoveredMarker.lat}</TableCell>
      </TableHead>
      <TableHead>
        <TableCell>lon</TableCell>
        <TableCell>{hoveredMarker.lng}</TableCell>
      </TableHead>
    </Table>
  </Box>
</InfoWindow>
```

`0.05 * 2^(-zoom+10)` — 줌이 커질수록(확대) 지수가 작아져 오프셋이 준다. 화면상 말풍선~마커 간격을 줌과 무관하게 비슷하게 유지하려는 보정이다.

<Callout type="tip" label="핵심:">
  클러스터는 상세창을 막고 단일만 열어주는 게 UX의 핵심이다. 뭉친 상태에서 억지로 정보를 보여주기보다, **"더 보려면 확대하라"** 는 신호를 자연스럽게 준다.
</Callout>

### 7. 삽질 포인트 — 직접 구현의 함정들

굴러는 가지만, 뜯어보면 알아둬야 할 한계가 여럿 있다.

#### 1) 결과가 입력 순서에 의존한다

그리디 방식이라 **`positions` 배열 순서가 바뀌면 클러스터 결과도 달라진다.** 먼저 들어온 점이 씨앗이 되고 뒤 점들이 그 중심에 흡수될지 판정받기 때문이다. 같은 데이터라도 정렬이 다르면 덩어리 모양이 미묘하게 달라진다.

#### 2) 구간 경계에서 클러스터가 "점프"한다

`variable`이 20 → 4 → 0.1로 계단식이라, 줌이 4에서 5로 넘어가는 순간 반경이 5.0 → 0.8로 급변한다. 사용자 눈엔 **덩어리가 뚝 끊기며 확 풀리는** 것으로 보인다. 부드러운 전환이 필요하면 `variable`도 연속 함수로 바꿔야 한다.

#### 3) key를 index로 쓰고 있다

`key={index}`는 클러스터 배열이 매 줌마다 재생성되면서 순서가 바뀌면 **React가 마커를 잘못 재사용**할 수 있다. `cluster.names[0]`처럼 안정적인 값을 key로 쓰는 게 안전하다.

<Callout type="error" label="주의:">
  `google.maps.Size` / `Point`는 **구글맵 스크립트가 로드된 뒤에만** 존재한다. 아이콘 정의를 렌더 시점에 만들다 보니, 스크립트 로드 전에 컴포넌트가 그려지면 `google is not defined`로 터진다. `@react-google-maps/api`의 `isLoaded` 가드 뒤에서만 렌더해야 안전하다.
</Callout>

### 8. 회고

#### 얻은 것

- 라이브러리 없이 **줌 구간별로 뭉치는 강도를 완전히 제어**하는 클러스터링 확보
- 클러스터엔 `+개수`, 단일엔 이름·상세 InfoWindow로 **정보 밀도를 줌에 맞게** 조절
- zIndex·오프셋 보정으로 **겹침·가림 문제**까지 정리

#### 다음에 개선하면 좋을 것

- `variable` 계단식 → **연속 함수**로 바꿔 구간 경계 점프 완화
- `key={index}` → 안정적인 식별자로 교체
- 클러스터 클릭 시 **해당 영역으로 줌인**하는 인터랙션 추가

#### 마치며

클러스터링은 "라이브러리 넣으면 끝"처럼 보이지만, 직접 구현해보니 **거리 정의·순서 의존성·줌 전환·겹침 처리**라는 지도 특유의 문제들이 줄줄이 딸려 나왔다. 지금 규모에선 단순한 그리디로 충분했고, 오히려 그 단순함 덕에 줌 구간별 튜닝과 라벨·상세창 같은 UX 디테일을 자유롭게 얹을 수 있었다. 스케일이 커지는 순간 위 개선 목록을 하나씩 꺼내 쓰면 된다.
